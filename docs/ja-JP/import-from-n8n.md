# n8n からインポート

Navide は、n8n からエクスポートしたワークフローを新しい Pipeline に変換できます。インポートは一方向・一回限りです。Navide はワークフローから Pipeline を作り、（マスク済みの）ワークフロー JSON をこのマシン上で Pipeline の隣に保存します。n8n に書き戻すことはなく、既存の Pipeline を上書きすることもありません。

## ワークフローをインポートする

1. n8n でワークフローをエクスポートし（Download、またはノードをコピー）、JSON を取得します。
2. Navide で **Pipeline Manager** を開き、**n8n からインポート** を選びます。
3. JSON を貼り付けるか、**ファイルを選択…** を使います。
4. Agent のステップを実行する CLI を選びます（既定は Claude）。AI Agent ノードはモデルから自分の CLI を選びます：Anthropic → Claude、OpenAI → Codex、Gemini → Gemini。
5. **プレビュー** を選びます。この時点では何も書き込まれません。プレビューを確認します（下記）。
6. **インポート** を選びます。新しい Pipeline が開きます。使用中の名前には「 (2)」「 (3)」… が付きます。

Agent は MCP ツール `pipeline_import_n8n` で同じことができます。既定は dry run で、同じレポートを返します（[外部 MCP 制御](external-mcp-control.md) を参照）。ワークスペースで Pipeline の実行中は、インポートは拒否されます。

## プレビューの見方

キャンバスは、各ステップがどう変換されたかで色分けされます。

- **そのまま変換**：Navide がワークフローの意図どおりに実行します。Manual・Chat・Execute Workflow トリガー、AI Agent クラスター（モデル、メモリ、ツール、出力パーサーは一つのステップにまとまります）、Wait と send-and-wait の承認（Gate）、IF と Switch（分岐）、Append または Choose Branch モードの Merge、エラー出力とリトライです。
- **エージェントが実行**：HTTP Request、Code、Set、データを結合する Merge（フィールド、位置、全組み合わせ、SQL。Agent がその結合ルールに従います）、アプリのノード（Google Sheets、Slack、Gmail…）、コミュニティノード、未知のノード種別やバージョンです。CLI Agent がノードの元のパラメータからステップを実行し、expression と Code はそのまま渡されます。結果は n8n と異なることがあります。分岐のない連続したステップは一つのステップにまとまるため、ノードごとに Pane が開くことはありません。
- **要確認**：インポートされますが、Navide にまだ無い機能が必要です。Schedule・Webhook・Form・アプリのトリガー（Pipeline は手動で開始してください）、Respond to Webhook、Execute Workflow と Call n8n Workflow Tool（サブワークフロー：参照先のワークフローもインポートしてください）、n8n に残すべきステップ（下記。**未対応** と表示されます）です。

キャンバスの下のレポートには、各 n8n ノードが何になり何をすべきか、各ステップの Kickoff 全文と各 Gate のプロンプト（各 Pane が受け取る文面そのもの）、設定が必要な認証情報、秘密が取り除かれた場所、確認が必要なステップ数が並びます。どれも **インポート** を妨げません。実行前に把握するためのものです。

### 分岐、エラー、リトライ、ステップ間のデータ

- **IF** は `true` / `false` の分岐エッジになります。**Switch** はルールごとに一つの分岐（名前を変えた出力はその名前、それ以外は番号）になり、fallback 出力は `default` になります。そのステップの Agent が選んだ分岐を報告し（`---BRANCH: <値>---`）、その分岐だけが実行されます。後ろの Append または Choose Branch モードの Merge は実際に届いた入力で実行されます。
- **On Error → Continue (using error output)** のノードにはエラーエッジが付き、失敗したときだけ次のステップが実行されます。自分自身をエラーワークフローにしているワークフロー（Settings → Error Workflow）では、Error Trigger の後のステップがすべてのステップからのエラーエッジとしてつながります。
- **Retry On Fail** はそのステップのリトライになります：合計で最大 5 回、間隔は最大 300000 ms です。n8n の設定がこれを超えるノードは、レポートに示されます。
- `$('Lookup').item.json` のように他のノードを読む expression は、Kickoff でそのステップの結果を `{{node.<ステップ id>.output}}` として受け取ります。読まれる側のステップには、最後に結果を JSON で出力するよう指示されます。

## 認証情報と秘密

認証情報はインポートされません。レポートは、ワークフローが使う認証情報を種別と名前、使っているノードとともに並べます。n8n の credential id は保持しません。代わりにこのマシンでアクセスを設定してください：**Settings → MCP** でそのサービスの MCP サーバーを追加するか、サービス自身の CLI ログイン（例：`gh`、`gcloud`）を使います。Pane の環境変数には何も入れません。

ワークフロー自体に書き込まれた秘密（Authorization ヘッダー、API キー、bearer トークン、その他よくあるトークンの形。cURL インポートで残りがちです）は、保存されるワークフロー JSON も含め、すべて `<removed: add credential for …>` に置き換えられます。レポートにはどのノードのどのフィールドから取り除いたかだけが載り、値は残りません。

保存されたワークフロー JSON と認証情報のリストはこのマシンにだけ残ります。設定バンドルのエクスポートには含まれず、Pipeline はどの Cloud 同期や共有にも含まれません。

## インポートした内容は外部コンテンツ

ワークフローから取り込んだもの（パラメータ、メモ、プロンプト）はすべて外部コンテンツとして扱われます。インポートした Pipeline は Pipeline Manager とエディターに **n8n から取り込み** と表示され、各 Kickoff の冒頭に外部コンテンツの注意書きが入ります。誰が開始しても、実行のたびにその Pane には Navide Guard の外部コンテンツのマークが付きます。このマークはオフにできません。自分で書いていないワークフローを実行する前に、プレビューで Kickoff を読んでください。

## n8n の MCP サーバーでステップを n8n に残す

大量の決定的なデータ処理、バイナリファイルの流れ、ベクトルストアなど、n8n に残した方がよいステップもあります。レポートはそれらを **n8n に残す** と示し、そのステップは n8n 自身の MCP サーバー経由でその n8n ワークフローを呼び出せます。メニュー名や利用可否は n8n のバージョンによって異なります。インスタンスの実際のバージョンに従ってください。

1. **n8n で**、owner または admin がインスタンスレベルの MCP アクセスを有効にします（Settings → Instance-level MCP → Enable MCP access）。
2. **Navide をクライアントとして接続します。** **Connect a client** の **API key** タブで、Server URL（末尾は `/mcp-server/http`）とアクセストークンをコピーします。トークンが完全に表示されるのは一度だけです。
3. **Navide で**、**Settings → MCP** に MCP サーバーを追加し、その URL と、`Authorization: Bearer <token>` ヘッダーとしてトークンを設定します。トークンはこのマシンでだけ入力します。MCP 同期が同期するのはインストールされているサーバーで、トークンは同期しません。
4. **ワークフローを公開します。** n8n でそのワークフローの **Available in MCP** をオンにします（ワークフローの `…` メニュー → Settings）。または Workflows enabled ページで有効にします。
5. **実行します。** Agent が n8n の `execute_workflow` ツールを呼びます。Navide はその n8n の実行の完了を待たず、結果を次のステップに渡しません。結果は n8n で確認してください。

出典：n8n のドキュメント「Connect to n8n MCP server」（docs.n8n.io/advanced-ai/accessing-n8n-mcp-server）。

## 既知の制限

- Execute Workflow と Call n8n Workflow Tool は、Navide にサブ Pipeline ができるまで保留のままです。
- `pinData` は Kickoff 内のテスト入力になり、出力を固定したステップにはなりません。
- ステップが約 8 個を超えると警告だけが出ます。各ステップが CLI Pane を一つ開きます。
- ノードの対応表は n8n の公開ドキュメントに基づき、ノード種別とバージョンごとに整理しています。未知のノードは Agent が代行し、確認が必要と示されます。
